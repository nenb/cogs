## Context

The final hostile pre-push review in `/tmp/native-final-review.md` found no P0 and confirmed the sandbox self-creation, runtime mount verification, PID ancestry, anonymous byte comparison, selector gating, compiler/zstd boundary, production-runtime readability, workflow trigger, capability boundary, and retained numeric production caps. It kept the gates closed on P1-01 through P1-03 and P2-01 through P2-02.

The remaining defects are evidence defects, not authority to redesign production. The process companion names the fault matrix but does not authenticate every injected outcome, and its recovery case hand-constructs started and settlement records around a non-archive child instead of obtaining them from a genuine failed or non-terminal production archive operation. ADR 0072's aggregate-counter language also overreaches by demanding interception of internal production metadata reads and writes, while the implementation still fails to account for the complete fixture-induced production resource domain, reserve before effects, reconcile partial effects, or bound all regular-file and pipe I/O; it also contains a blocking `waitpid(pid, 0)` after its deadline. A fork-only recovery process could inherit exactly the application state that durable recovery is intended to displace. The TypeScript checks bind labels and fragments rather than the complete reviewed verifier predicates, and a mutation can be rejected only by the digest gate instead of semantics. Finally, post-child pathname removal of the evidence parent leaves an avoidable race.

The schema observation is different. `schemas/stage2-phase-b-qualification-v1.json` must be tracked in the exact final commit under retained ADR 0070 authority, but an untracked pre-commit working-tree file is not itself a production or schema implementation defect. It is evidence that no exact reviewable final head yet exists. Final signoff still fails unless the exact final commit tracks that schema and every reviewed implementation file.

The review measured the five excluded surfaces from exact baseline `18f26441b6115091233d0c4cd44ced8f058d014f` at 225, 538, 34, 642, and 412 gross additions, or 1,851 aggregate. The narrow authentic-recovery, accounting, static-proof, and evidence-directory corrections require readable room beyond some ADR 0072 highs. This ADR changes no production maximum.

### Genuine production fault and recovery evidence

ADR 0072's failed and non-terminal archive recovery requirement remains mandatory. The selected native process route must create a genuine generated archive input and execute the actual production archive child. The operation itself must invoke the actual child callbacks and real production persistence path: the child callbacks must durably create the started and settlement records, the injected actual child failure must produce the production-defined durable non-terminal settlement that later recovery consumes, and the real recovery callback must durably create the recovery record. The separate failed case must likewise obtain its terminal failed settlement from the genuine archive operation and callbacks. Hand-constructed, synthetic, test-substituted, preseeded, directly injected, or callback-adjacent rows cannot satisfy either case. A generic Python leader/descendant, a separately called callback around a genuine child, or any route that does not execute the production archive path is not evidence.

The matrix must authenticate the failed settlement and non-terminal settlement separately. Later recovery must be launched as exact empty-environment `/usr/bin/env -i` followed by `execve` of a new `/usr/bin/python3 -I -B` interpreter and must enter through the real production runner CLI cleanup/recovery entry, not a directly imported or called internal helper. At entry the recovery interpreter may inherit only fixed authenticated descriptors 0, 1, and 2; every descriptor numbered 3 or greater must have been closed before `execve` and absence must be proved. Isolated mode, the empty environment, and replacement of the process image must exclude inherited imported modules, callbacks, monkeypatches, ownership sets, open application descriptions, `PYTHONPATH`, `sitecustomize`, and all originating application/test state. The new interpreter must load only the durable production-created records through the production CLI, prove exact signaling, bounded settlement/reaping, and independent absence of the archive leader and every descendant, and then prove descriptor, row, process, pathname, pipe, anonymous-inode, and fixture zero residue. A plain `fork`, multiprocessing child without exec, in-process reset, direct recovery helper call, or inherited descriptor/application state is not fresh recovery. Genuine production gzip and zstd success and fault coverage, authenticated release, low/high `close_range`, PDEATH/reparent behavior, and every retained ADR 0072 production-seam requirement remain mandatory.

Every named injected fault must be authenticated through an observation that crosses the fork boundary when applicable. Parent-only mutation of a list after a child-side callback is not proof. The test must establish the expected production callback/effect, expected exception or settlement class, and required cleanup or recovery result. Catching every exception without checking its type and resulting settlement, or excusing an unobserved child-side seam, fails.

### Complete fixture-induced resource accounting

This section supersedes ADR 0072 only where that ADR requires counters or deadlines to intercept every opaque internal production metadata helper operation. The accounting ownership domain is transitive and causation-based, not limited by which process or layer performs an effect. It includes every resource induced by a companion fixture or fault case, whether created by harness or production code: every owner, report, export, runtime journal, journal staging/temporary/lock, archive input/output, and other temporary pathname and every archive descendant pathname; every generated fixture; every anonymous inode; every archive leader and all descendants; every pipe; and every descriptor and open file description. A hard link is a separate live pathname, each descriptor is separately live, and production ownership does not remove a resource from this domain. A resource remains in the domain through settlement, recovery, and authenticated cleanup.

The unchanged per-companion highs are: each generated fixture at most 64 KiB, aggregate fixture-induced harness writes at most 1 MiB, aggregate fixture-induced harness reads at most 8 MiB, at most 16 simultaneously live temporary pathnames, and at most 16 simultaneously live descendants. The write aggregate includes every regular-file and pipe byte the harness transfers to construct, control, or fault a case; the read aggregate includes every regular-file and pipe byte the harness consumes from fixture-induced output or control state, including a reread after reopening. Each actual transferred byte is committed once for that I/O effect: chunking neither loses nor duplicates a charge, but a later reread or rewrite is a new transfer and is charged again. Opaque production-internal metadata I/O need not be monkey-patched solely to count its bytes, but every production-created resource and every harness observation of it remains covered. Each companion must also declare before execution exact finite live inventory highs for its fixture, anonymous-inode, pipe, descriptor, and open-description classes; no class may be dynamically derived from the observed peak or treated as unbounded. All byte totals and peaks are monotonic, and every current live count must return to zero.

Before every operation that can create, open, link, fork/spawn, or transfer bytes, the companion must reserve the operation's conservative maximum effect against every applicable aggregate and live-class high. This includes a production seam that may create owner/report/export/journal/temp pathnames or archive descendants, `open`/`pipe` and descriptor duplication, anonymous-inode creation or publication, every link, every fork, and every regular-file or pipe read/write. A pipe reserves one pipe and both descriptors; a link reserves its new pathname; a fork reserves the leader and the maximum descendants that the invoked production route can create; and an I/O attempt reserves its maximum requested transfer before the syscall. If all applicable capacity is not available, the effect must not be attempted. Reserved plus authenticated-live capacity is the current count for cap enforcement and peak calculation, so no success, before-effect fault, after-effect fault, callback, or observation may create even a transient seventeenth pathname/descendant or otherwise exceed a declared cap.

Immediately after every attempt, including success, a proved before-effect fault, a partial effect, and a close- or other after-effect fault, the companion must reconcile the reservation from authenticated observation of what actually occurred. Authentication must use the applicable identity-bound directory/descriptor metadata, durable production callback records, pipe/offset/length evidence, and PID/pidfd/wait/ancestry evidence rather than an assumed callback or detached counter. A proved before-effect fault may release only capacity whose absence is authenticated. Success or an after-effect fault converts the observed part of the reservation into the corresponding monotonic byte charge or live resource, and live capacity is released only after authenticated destruction/reap/close. A partial transfer commits the observed bytes; uncertainty conservatively commits or retains the full reservation and fails rather than understating use. Before/after-effect injection cannot erase an earlier charge, and reconciliation after the call cannot excuse a transient cap breach. Pathname, inode, fixture, process, pipe, descriptor/open-description, and byte ledgers are independent even when one syscall affects several.

Every operation that can block must have its own fixed absolute monotonic deadline no greater than 30 seconds around the operation itself. A descriptor whose nonblocking syscall is guaranteed to return without sleeping must use nonblocking mode plus bounded selector readiness against that deadline. Every regular-file read, write, `fsync`, or close—and every other operation for which nonblocking mode cannot itself enforce the bound—must instead be enclosed by a process-local `SIGALRM` armed with `setitimer(ITIMER_REAL, ...)` before the syscall and reliably disarmed/restored afterward; selector readiness alone is prohibited for those operations. This requirement expressly includes pathname create/mkdir/open/link/rename/unlink/rmdir, anonymous-inode open/publication, descriptor open/dup/pipe/close, fork/spawn, regular-file read/write/fsync/close, and pipe read/write/close effects. Pipe descriptors must be nonblocking and selector-gated. Child waits, settlement waits, and reap loops must use `waitpid(..., WNOHANG)` or equivalent nonblocking polling against the same kind of per-operation deadline. After timeout, blocking `waitpid(pid, 0)`, an unbounded join, sleep-as-wait, a retry without a new bounded reservation, or any unconditional blocking cleanup is prohibited; timeout is failure followed only by separately reserved, bounded cleanup and authenticated proof. The exact outer `/usr/bin/timeout --signal=KILL 240` remains mandatory per companion and does not replace any operation deadline.

Final runtime assertions must prove every declared high and reservation/reconciliation transition, exact monotonic byte totals, independently authenticated per-class current/peak state, no transient over-cap effect, every bounded operation outcome, and zero fixture/pathname/anonymous-inode/process/pipe/descriptor/open-description residue. Static companions need not pretend to count opaque production metadata transfer bytes, but must bind and semantically test this exact transitive domain, pre-effect reservation, after-attempt reconciliation, and deadline contract.

### Canonical static exactness plus semantic mutation proof

The TypeScript companions must no longer treat retained error-label substrings, command fragments, or high literals as proof of complete verifier predicates. Static exactness may be established by a literal lowercase SHA-256 digest binding of the complete reviewed `native-runtime-preflight` job, including its entire embedded mount/evidence verifier, and of each complete reviewed native accounting/matrix region on which the companion relies. The canonical byte selection must be deterministic, cover every executed helper transitively relied on by the claimed region, reject CR or ambiguous/duplicate boundaries, and be documented in the companion. Omission, duplicate selection, parse ambiguity, non-lowercase/non-64-hex digest, or any exact digest mismatch fails before semantic assertions. A fragment or digest of labels alone is insufficient.

A digest is exact-change detection, not semantic approval. Each TypeScript companion must expose and invoke the actual semantic validator used for its ordinary canonical selection; a regex, copied model, parallel oracle, retained label, or assertion over unmodified source is not that validator. For every required hostile mutation, the test must mutate the canonical selected workflow/Python bytes themselves, recompute and rebind the digest to that exact mutated selection for that mutation test only so the hash gate succeeds, invoke the actual semantic validator on those mutated bytes, and prove that the semantic predicate—not the digest gate—rejects them. The checked-in digest and ordinary path must remain unchanged by this test-only rebinding.

The mount verifier mutation cases must reject missing, duplicate, reordered, added, writable, wrong-source, wrong-size, wrong-mode, wrong-type, wrong-device, wrong-root, wrong-parent, and wrong-option records, including a tautological device or bind-identity comparison that retains the old error label. Evidence mutations must reject reordered or omitted unlink/fsync/link-count-zero operations and child-visible path/descriptor variants. Process and accounting mutations must reject synthetic recovery rows, fork-only or internal-helper recovery, inherited application state/descriptors/patches, an unauthenticated post-fork fault, omitted reservation or reconciliation for any covered create/open/link/fork/read/write/remove/reap effect, byte double charging or uncharged I/O, and a blocking or unbounded post-deadline operation.

A separate ordinary hash-mismatch test must alter an otherwise semantically acceptable canonical selection without rebinding its stored digest, invoke the ordinary complete validator path, and prove exact digest rejection occurs before the semantic validator. Thus semantic rejection cannot be self-fulfilled by SHA-256 mismatch, while semantic success can never excuse an ordinary exact digest mismatch. Final hostile review must record the canonical selections, exact checked-in digests, ordinary mismatch result, each mutated selection's test-only rebound digest, and the actual semantic-validator rejection it reviewed.

### Pre-launch unlink of the exact evidence directory

Supersede ADR 0072's post-child pathname cleanup of `$RUNNER_TEMP/cogs-native-runtime-evidence`. The trusted outer workflow code must complete all evidence pathname removal before launching `sudo`, `setpriv`, or `unshare`.

After both exact leaf names are unlinked through the retained private-directory descriptor, the private directory is fsynced, and both retained leaf descriptors prove link count zero, trusted code must revalidate the private directory's captured device/inode/type/owner/mode identity. While retaining its open descriptor, it must remove the exact private-directory name through the retained, identity-bound runner-temp directory descriptor, fsync the runner-temp directory, and prove by `fstat` on the retained private-directory descriptor that the captured directory itself has link count zero. Failure or identity uncertainty fails before child launch.

The retained private-directory descriptor remains outer-only and is never inherited by the child. During and after the child there is no evidence pathname to resolve, rename, replace, compare, or remove. After status, anonymous-leaf metadata, and descriptor-backed byte validation, outer code closes the retained expected, output, and private-directory descriptors. Post-child cleanup is descriptor closure only; pathname cleanup, pathname revalidation, or broad removal is prohibited. This proves reclamation from retained anonymous identities and removes the P2-02 pathname race.

## Final root-protected retirement correction plan at `cfcb1012`
Reviewed inputs: `/tmp/cogs42-rootcustody-plan-a.md` and `/tmp/cogs42-rootcustody-plan-b.md` conditionally accept the direction, not implementation closure. This amendment specifies the missing conditions; planning/governance only, no source changes or execution authority. It supersedes any implication above that quarantine deletion or catch-time veto recreation alone settles retirement.
- **Trust boundary:** require genuine host-root in the real initial user namespace, not userns UID 0; EUID alone or comparison with a namespaced PID 1 is insufficient. Establish kernel-backed initial-namespace identity under the trusted host launch boundary; missing UID/namespace APIs or unverifiable host provenance refuse before effects. Root, host launcher/worker code and source installation are trusted; no malicious-root resistance claim. No sudo, silent elevation or adoption/chown of existing nonroot custody.
- **Protection from creation:** descriptor-anchor and validate UID-0, nonroot-unwritable ancestry from a trusted host root through source installation, state, authority/control files, temporary cleanup, quarantine and journal; private custody directories are 0700 and records 0600. A root-owned leaf under a renameable parent is insufficient. Serialize trusted writers; prohibit ACL/mount exceptions, inherited nonroot-writable handles and any writable guest/workload alias or exposure to these inodes. Later chmod/chown cannot revoke prior handles and cannot establish this provenance.
- **Admission:** one production-hardwired `assertHostRoot()` (no override) at every effectful ingress: CLI before its first mkdir, `resolveLauncherState` before `ensureRoot`, direct state/acquisition/control/temp helpers, core/operations, supervisor start/stop, profile driver invocation and direct insecure driver before tools/spawn or acquisition. Check custody defensively at mutations/retirement too; inventory must report pending independently of phase/recovery or fail closed. Missing kernel, exclusive-create, nofollow/descriptor, filesystem durability or journal capability refuses pre-effect; runtime loss fails closed. Pure inspection must not create custody.
- **Bounded structure/test seam:** keep the closed bounded journal codec/replayer, admission and retirement owner in existing `dev/launcher/state.ts`, not a new privileged helper/framework. A private implementation factory binds the immutable production facade to kernel checks, UID 0 and real filesystem; separate explicit test instances model ownership and faults coherently with private state/scope registries. No request/options/environment/CLI flag, mutable setter, caller predicate, production `allowNonRoot` or public recovery fault hook can select/bypass production custody; test objects cannot enter it. Trusted arbitrary privileged JavaScript execution is outside this guarantee.
- **External additive exclusion:** retain durable per-state transaction history outside every state/lock/quarantine removal subtree, under equally protected persistent ancestry (not a reboot-volatile substitute). Bind a closed versioned record to exact canonical state locator, held parent/state identity or explicit pre-creation absence, transaction sequence and exact retirement custody. Reserve the next per-state slot exclusively before admission; competing callers cannot both proceed. An empty/incomplete reservation is pending/malformed. Never unlink, truncate, overwrite, compact or automatically delete journal slots/records; exhaustion/unsupported bounds refuse rather than discard history.
- **Replay/admission:** under exclusive custody, literally enumerate and validate the complete bounded ordered history and surviving custody. Every unresolved, torn, malformed, foreign, contradictory, duplicate, legacy-uncertain or newly pending slot vetoes ordinary reuse and driver effects, including after state removal/restart. Older COMMIT cannot mask newer BEGIN/reservation; no inference of ownership/settlement from absence. Pending remains authoritative across state-lock removal through terminal publication; a second caller cannot race into that gap.
- **Order:** exclusive slot reservation and fully durable BEGIN (record and all newly created directory entries/parents fsynced) precede lifecycle effects. Then await callback and all its finally cleanup; exact descriptor-bound quarantine/move/revalidation; all file/control/temp retirement and empty-directory/lock-directory removals; required absence checks and parent/directory fsyncs; and every retirement-related handle close. Only then publish terminal COMMIT in that slot additively. Catch-time mkdir is not crash durability; unknown/mismatched files AND empty directories remain preserved, never adopted/deleted.
- **Scoped ownership:** `withStateLock(state, async scopedState => ...)` owns the transaction; a privately runtime-registered, nonforgeable borrow binds exact runtime/state/transaction and active callback. Only that scope can bypass its own pending slot, never another. Reject expired, copied, cross-state/cross-runtime or concurrently reused scopes; no ambient WeakMap join, exported settle/ignorePending/alreadyLocked switch or nested owning transaction. Inner helpers borrow descriptors, do not commit or close caller-owned handles; each handle has exactly one close owner. Await all actual cleanup/closures (not fail-fast aggregation) and retain every failure; swallowed inner failure taints the outer transaction permanently and forbids COMMIT/success.
- **Direct helper scopes:** `clearRecovery(state)` and `removeOwnedState(state, authority?)` borrow only an authentic active scoped state; otherwise each opens its own owning transaction. Clear includes recovery retirement, final absence, sync and close, even on the already-absent path; remove includes exact authority validation, all member/tombstone/state/lock directory retirement, absence, sync and close. Only the outer owner settles after lock release and all callers' cleanup; no post-COMMIT resource-retirement work. Existing acquisition-uncertainty and one-shot driver-destroy checks remain independent; COMMIT permits another admissible operation, never replay/adoption of retired authority.
- **Commit uncertainty:** resource-retirement obligations end before terminal publication; publication's own write/fsync/close is the commit boundary, not an infinitely recursive retirement obligation. Report success only after durable COMMIT acknowledgment. Any publication error fails that invocation and retains history: disk may contain pending, malformed or complete COMMIT with uncertain acknowledgment. Do not promise permanent veto for every publication error or turn a failed invocation successful later. No catch-time retry/delete/rollback/replacement receipt can repair an uncertain acknowledgment.
- **Fresh reader durability:** before accepting a complete terminal record, a fresh process takes exclusive custody, revalidates its exact BEGIN/transaction/history and protected identities, and establishes durability of terminal file plus containing directory and relevant ancestors, including successful handle settlement; mere readable COMMIT is insufficient. Reader validation/fsync/close failure refuses. A complete valid durably established COMMIT may admit a later operation despite prior acknowledgment uncertainty; incomplete/malformed/pending remains vetoed. This is crash-safe refusal with operator intervention, not automatic recovery: no replay/resume of retirement or uncertain driver destroy is authorized here.
- **Independent insecure driver:** `dev/insecure-sandbox/driver.sh` must own its own root-protected external per-state exclusive additive BEGIN/COMMIT journal even without a launcher. Both Python cleanup paths (`docker_tool_custody` and `file_custody`) encompass quarantine, lock/state/empty-directory removals, final absence/fsync/close before terminal publication, with the same uncertainty and fresh-reader rules. Launcher settlement cannot substitute. Replace `compgen -G` with literal directory enumeration and literal prefix matching; enumeration errors veto. Retained successful custody is distinguished only by authenticated committed status, never mere existence; unresolved/legacy custody still vetoes. Nested launcher/driver layers each own only their journal and must observe inner settlement failure.
- **Required portable closure tests (not run/claimed here):** real nonroot and missing UID/namespace API refusal before mkdir/lock/spawn/injected callbacks; userns-root refusal; unsafe ancestor, preexisting/chowned custody, writable alias and missing durability capability refusal; production binding not selectable by test flags/objects; protected Linux success and repeated clean lifecycle with retained receipts. Preserve old-source replacement coverage and target actual quarantine unlink/rmdir boundaries, including foreign files and empty directories.
- **Required scope/crash tests:** direct and scoped clear/remove, already-absent clear, swallowed inner failure/sticky taint, expired/copied/cross-state/cross-runtime/concurrent borrows, one close owner and awaited-all closure failures; before/after-effect faults at BEGIN/reservation, callback/finally, file/directory removal, lock release, every fsync/close and COMMIT write/fsync/close; competing admission during lock-release/publication gap; fresh-process restart with removed state and pending/malformed/newer slots, complete-COMMIT uncertain acknowledgment and fresh-reader durability failures; inventory veto and repeated committed history.

### Self-created exact future root

Supersede ADR 0071's `/sandbox` construction, verification, and chroot path with this exact layout. There is no ambient `/sandbox` prerequisite. The trusted shell must not inspect, create, mount, bind, enter, or rely on `/sandbox` in the old root or future root.

After the irreversible host runner UID/GID and group drop, host `no_new_privs`, fresh user/network/PID/mount namespaces, first descriptor closure, and recursively private propagation required by ADR 0071, the trusted namespace-root shell must:

1. mount a fresh namespace-private tmpfs with exact source `cogs-native-stage` and exact construction contract `size=32m,mode=0700,nosuid,nodev,noexec` over exact old-root `/tmp`, thereby hiding every host `/tmp` pathname and socket and bounding all staging state;
2. only after that mount succeeds, create exact `/tmp/cogs-native-runtime-root` as a new empty directory in the fresh tmpfs;
3. mount the fresh 16 MiB `mode=0700,nosuid,nodev` future-root tmpfs directly at exact `/tmp/cogs-native-runtime-root`;
4. beneath that exact root, create only the trusted empty targets and bind read-only host `/usr`, each of host `/lib` and `/lib64` that exists, and the exact checkout at `/src`, with ADR 0071's unchanged `ro,nosuid,nodev` and `/src` `noexec` requirements;
5. mount the separate fresh 16 MiB `mode=1777,nosuid,nodev,noexec` tmpfs at the future root's `/tmp`, mount the fresh read-only `nosuid,nodev,noexec` procfs for the new PID namespace at its `/proc`, and bind only exact host `/dev/null` and `/dev/urandom` at their exact future-root names with the retained read-only `nosuid,noexec` restrictions; and
6. after complete verification and the second descriptor closure, terminally `exec` exact host `/usr/sbin/chroot /tmp/cogs-native-runtime-root` with no chroot option. The trusted namespace shell is PID 1 in the fresh PID namespace and may not fork or retain an old-root waiter or monitor there. Successful `chroot(2)` must make that exact directory the process root and reset cwd so the in-root root and cwd are both exact `/` before in-root setpriv and Python resolve.

The future root is never moved over old `/`, and old `/` is never covered. Inside the chroot there is no `/tmp/cogs-native-runtime-root` transition path: the future root is simply `/`. PID 1 has terminally replaced itself with the chroot chain, so the fresh in-root procfs exposes no process retaining the old root. The outer fixed workflow shell remains outside all child namespaces. The required `unshare --fork` waiter shares the new user, network, and mount namespaces with the forked child, but `--pid` applies the new PID namespace only to subsequently created children, so that waiter stays in the ancestor PID namespace and outside the child PID/proc view. Within the `unshare` launch tree the old-root view is retained only by that waiter; the child cannot see it through its procfs or otherwise address it from the child PID namespace. The ban is therefore narrowly on any old-root process visible or addressable from the child PID namespace, not on this required ancestor-PID-namespace waiter. The source-bind allowlist, fresh unconfigured network namespace, securebits lock, empty capability sets, namespace UID/GID 0, second `no_new_privs`, empty environments, literal companion paths, and every other non-conflicting ADR 0071 isolation rule remain unchanged.

Use fixed source labels for the three newly mounted filesystems so trusted verification can distinguish them: exact `cogs-native-stage` for old-root `/tmp`, `cogs-native-runtime-root` for the future-root tmpfs, and `cogs-native-runtime-tmp` for the in-root `/tmp`; procfs source remains exact `proc`. The staging mount must be constructed and verified as exactly a 32 MiB, mode-0700 `nosuid,nodev,noexec` tmpfs. The future-root and in-root `/tmp` mounts retain their exact existing 16 MiB contracts, labels, modes, and required/prohibited options without change. A missing source, unsupported mount behavior, size or mode mismatch, extra permissive option, or unexpected normalization is failure, not permission to weaken verification.

### Complete mount verification

Before checked-out code, trusted code must parse complete `/proc/self/mountinfo` records rather than accepted substrings. It must decode mountinfo escapes and validate mount ID, parent ID, major:minor device identity, mount root, mount target, complete VFS options, optional fields, filesystem type, mount source, and complete superblock options. Malformed, duplicate, ambiguous, undecodable, or unexamined data fails.

Each expected target must occur exactly once, independently of every other target. One aggregate count is insufficient. Verification must cover old-root `/tmp`, exact `/tmp/cogs-native-runtime-root`, and every expected mount below that root: `/usr`, optional `/lib`, optional `/lib64`, `/src`, `/tmp`, `/proc`, `/dev/null`, and `/dev/urandom`. It must reject every unexpected mount at or below the future root and every unexpected nested source mount. Parent mount IDs and mount roots must prove the exact hierarchy and bind origin rather than only pathname spelling.

For every target, verification must prove the expected filesystem type, source, major:minor identity, mount root, required and prohibited VFS options, and required and prohibited superblock options. The three fresh tmpfs mounts must have their exact distinct source labels, options, identities, and sizes; the proc mount must be the fresh PID-namespace procfs with exact source and restrictions. Each bind target must match trusted pre-bind source metadata and the source mount's filesystem type, source, major:minor identity, and adjusted mount root. Source and target `stat` identity must agree as applicable. `/dev/null` and `/dev/urandom` must additionally be character devices whose target inode and `st_rdev` identities match those exact trusted host devices; a same-named substitute is failure. Read-only bind verification must inspect the effective bind mount rather than infer it from the parent superblock.

The verifier must prove that each fresh mount has a new mount ID, that the fresh tmpfs identities are not the covered host `/tmp` identity or one another, and that no expected target is satisfied by a duplicate accepted target. For old-root `/tmp`, both construction and runtime/static verification must literally bind source `cogs-native-stage`, size 32 MiB, mode 0700, and `nosuid,nodev,noexec`; those values are not defaults or lower bounds. Static TypeScript companions must assert the complete construction order and mountinfo grammar and must reject a missing, duplicate, reordered, added, writable, wrong-source, wrong-size, wrong-mode, wrong-type, wrong-device, wrong-root, wrong-parent, or wrong-option mount. The static assertions supplement and do not replace runtime mount verification.

### Byte-exact outer anonymous-inode output protocol

Supersede only ADR 0071's companion-output command substitution and in-memory comparison. For each invocation, the fixed workflow shell outside and parent of `unshare` must validate the canonical runner-temp directory, bind its identity, and create this exact new private directory and two leaves before launching `sudo`, `setpriv`, or `unshare`:

- private parent `$RUNNER_TEMP/cogs-native-runtime-evidence`, exact mode 0700;
- expected leaf `$RUNNER_TEMP/cogs-native-runtime-evidence/expected`, exact mode 0600; and
- output leaf `$RUNNER_TEMP/cogs-native-runtime-evidence/output`, exact mode 0600.

The private parent must be a newly created directory with exclusive no-follow handling, ordinary runner ownership, and captured device/inode identity. Through a retained descriptor for that exact parent, the outer shell must create each leaf as a new regular file with exclusive no-follow semantics, ordinary runner ownership, link count one, and captured device/inode identity. It must open and retain the exact expected and output descriptors and verify descriptor/path identity, type, owner, mode, and link count before use. Pre-existence, a non-directory or changed runner-temp parent, symlink traversal, type or identity uncertainty, or failure to create and verify the exact private parent and leaves fails before launch.

Fixed trusted outer code, never checked-out code or namespace code, writes exactly the selected companion's literal marker plus one LF to the expected descriptor, handles partial writes, fsyncs the expected content, and verifies that the output descriptor still names the captured zero-length regular inode. It then unlinks both exact leaf names through the bound private-parent descriptor, fsyncs that parent, and verifies through both retained descriptors that each exact inode has `st_nlink == 0`. All of those operations must complete before child launch. From that point through final close both evidence inodes are anonymous: there is no leaf pathname to rename, link, or replace during child execution.

The retained expected descriptor is outer-only and must never enter the child-side launcher. The outer shell keeps the anonymous output inode open without pathname re-resolution, arranges that launch fd 1 refers to that exact open file description and fd 2 is duplicated from fd 1, and closes launch fd 0. The exact `sudo` close-from boundary must close every other child-side descriptor numbered 3 or greater. Thus the complete child tree inherits only fd 1 and fd 2, both directed to the same anonymous output inode; it inherits no expected, private-parent, identity, or separate output descriptor. The private parent and evidence inodes are not mounted or bound into the future root. The namespace PID-1 shell performs only fixed construction and verification and then terminally execs the exact chroot/setpriv/env/timeout/Python chain. It does not remain at the old root to wait or compare.

The outer waiting shell remains outside the child namespaces and waits for the fixed `unshare` chain, recording and validating its exact status without allowing a nonzero status to bypass evidence validation. After wait, it revalidates both retained anonymous descriptors, including exact device/inode identity, regular-file type, ordinary-runner owner, mode 0600, and link count zero. Trusted outer code must then either emit the selected literal marker plus one LF anew into a separate trusted pipe or descriptor, or rewind the retained exact expected descriptor; it must rewind the retained output descriptor and perform an exact byte-for-byte descriptor-backed `/usr/bin/cmp --silent --`. No comparison may resolve an evidence pathname. Success requires status zero and every identity, metadata, and byte comparison; any status mismatch, metadata change, short or extra output, or comparison error fails.

Companion output must never be placed in command substitution, a shell variable, text decoding, line processing, or another representation that can discard NUL or alter non-UTF-8 bytes. Exact `cmp` must therefore reject an extra NUL, non-UTF-8 byte, trailing or leading byte, duplicate marker, extra LF, stderr byte, or partial output. Only after the zero status and exact descriptor-backed `cmp` may the outer fixed code print the already-known literal marker once to its original job-log stdout; it must not print by reading untrusted output.

After validation on success or failure, the outer shell closes its retained expected and output descriptors. Because both inodes had link count zero before launch, final close reclaims them without any post-run leaf cleanup. While retaining and revalidating the exact private-parent and runner-temp descriptors, it removes the exact empty private directory through the bound runner-temp parent, fsyncs that parent, and then closes the parent descriptors; inability to complete that fixed parent cleanup fails the job. The TypeScript companions must statically assert private-parent and leaf creation before `unshare`, exact descriptor/path identity verification, expected write and fsync, pre-launch unlink and parent fsync, pre-launch link count zero for both inodes, non-inheritance of the expected descriptor, output duplication only to fd 1/2, outer closure of fd 0, exact `sudo` close-from of every fd 3 or greater, PID-1 terminal chroot, status collection, retained-descriptor byte comparison, final descriptor close, and the narrow prohibition on any old-root process visible or addressable from the child PID namespace. They must reject a child-visible evidence pathname or an expected descriptor anywhere in the child tree. The evidence is temporary test state only: the job creates and uploads no artifact, report, cache, attestation, or other retained object.

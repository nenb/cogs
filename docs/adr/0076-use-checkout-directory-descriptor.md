# ADR 0076: Use a narrow native checkout directory descriptor

- Status: Accepted
- Date: 2026-07-27
- Decision owner: Nick Byrne
- Accepted by: Delegated project lead on 2026-07-27 under Nick Byrne's standing authorization to complete all non-AWS work.
- Amendment scope: Correct only the trusted `native-runtime-preflight` checkout handoff exposed by native execution at `d87ff2e`, and narrowly ratify only the exact prior Gitleaks-fingerprint commit for the deterministic RFC 8032 synthetic test fixture. The ordinary runner opens and authenticates the exact canonical checkout as an `O_PATH` directory, normalizes it to fd 3 with the fixed subprocess inheritance protocol, and passes only fd 3 across the host-root launcher boundary. Synchronous trusted Python observers inspect quiescent namespace PID 1 before the exact non-canonicalizing descriptor bind and after fd 3 closes; PID 1 then immediately terminally execs chroot. Authorize only the existing CI workflow, its two existing TypeScript static companions under their retained highs, and the exact two-line root `.gitleaksignore` already introduced by exact commit `66f89ab36d25b006a646a82bd924bddeabd4b747`. Checked-in Python, production code, schema, events, runs, acquisition, and AWS boundaries do not change.

## Context

The native run at exact implementation head `d87ff2e3c01ab79505491cb06bbf3cb4efb019e8` reached the trusted sandbox but could not resolve the runner-owned checkout beneath `/home`. ADR 0075 intentionally maps only initial-namespace UID/GID 0 to namespace UID/GID 0. After `unshare`, that process has capabilities only in the new user namespace and none in the initial user namespace. Host-root DAC identity without initial-namespace capabilities therefore cannot use capability-based directory-search override to traverse a runner-owned ancestor that denies it search access.

Changing checkout or ancestor modes, adding an ACL, changing ownership, retaining the runner identity, or adding the runner UID/GID to the namespace map would weaken the exact one-ID boundary. Copying the checkout would stop testing the exact checked-out bytes. The ordinary outer runner already has legitimate access to the exact canonical checkout and can open one non-reading `O_PATH` directory reference before the identity transition. Passing only that authenticated reference removes ancestor traversal without granting pathname access, an additional identity mapping, or a general inherited-descriptor channel.

The same branch contains a Gitleaks finding for line 54 of `test/aws-stage2-completion-kata-inputs.py`. That line constructs an OpenSSH private-key envelope deterministically from published RFC 8032 test-vector material inside a hostile test fixture. It is not a credential, generated secret, production key, or reusable environment identity. The correct exception is the finding's complete immutable fingerprint, not a rule disable, path allowlist, regex, or repository-wide suppression.

### Outer exact checkout descriptor

The retained exact-head, same-repository, canonical-checkout, ordinary runner UID/GID, anonymous expected/output, and clean-tree checks remain mandatory. Before opening any retained evidence descriptor, the trusted outer `/usr/bin/python3 -I -` launcher must open the already-proved exact canonical checkout with `O_PATH|O_DIRECTORY|O_NOFOLLOW` and close-on-exec set in the outer process. It must compare `fstat` of that descriptor with no-follow stat of the exact canonical pathname and authenticate the directory type and exact device, inode, ordinary runner UID, and ordinary runner GID. A symlink, non-directory, changed identity, unexpected owner, noncanonical path, alternate worktree, caller-selected path, failed flag, or unavailable `O_PATH` fails before `sudo`.

Before any retained expected, output, private-parent, or runner-temp evidence descriptor is opened, the outer Python must normalize the authenticated checkout reference to descriptor number 3 with `os.dup2(checkout_fd, 3, inheritable=False)` and immediately close `checkout_fd` when it is a distinct alias; if the authenticated open itself returned 3, it must expressly set fd 3 non-inheritable and no alias exists. It must reauthenticate fd 3 after normalization. No duplicate checkout reference may remain. Fd 3 stays non-inheritable in the outer process. The one direct `subprocess.run` launch must use `stdin=subprocess.DEVNULL`, the anonymous output descriptor as `stdout`, `stderr=subprocess.STDOUT`, `close_fds=True`, and exactly `pass_fds=(3,)`; it must not use `preexec_fn`. `pass_fds` makes only fd 3 inheritable for the direct child exec. A `stdin=None` inheritance, closing fd 0 in a pre-exec hook, any other `pass_fds` tuple, broad inheritable set, general descriptor allowlist, or equivalent launch is prohibited. The runner-owned expected, output, private-parent, runner-temp, and checkout-alias descriptors remain outer-only. Thus launcher fd 0 is `/dev/null`, fd 1 and fd 2 refer to the retained anonymous output open description, and fd 3 is the sole descriptor at or above 3. The exact authenticated device/inode/host-UID/host-GID tuple is passed only as inert expected data.

The fixed prefix must use exact `sudo -n --close-from=4`, so `sudo` closes every descriptor at or above 4 while preserving fd 3. Every other ADR 0075 argument and ordering remains exact: host UID/GID 0 through `setpriv`, empty supplementary groups, `no_new_privs`, exact one-ID UID/GID maps, and fresh network/PID/mount namespaces. Static companions must reject `sudo --close-from=3`, any other close-from value, `sudo --preserve-env`, `-C` policy dependence, a shell before the fixed launcher, another passed descriptor, or a general descriptor allowlist.

### Namespace descriptor bind and terminal closure

Namespace PID 1 must not scan its own `/proc/self/fd`, use a shell fd glob, or rely on a helper proving the helper's descriptor table. While PID 1 is quiescent and waiting, its first synchronous trusted Python observer must derive its parent with `os.getppid()` and inspect `/proc/<ppid>/fd` and `/proc/<ppid>/fdinfo`; the observed parent must be namespace PID 1. The observer must require the parent's descriptor names to be exactly `0`, `1`, `2`, and `3`, and must authenticate parent fd 3 as the expected `O_PATH` directory reference with `FD_CLOEXEC` clear, exact device, inode, directory type, and expected namespace-visible UID/GID. It must also prove the exact one-ID maps, prove the authenticated nonzero host runner UID/GID are unmapped, and require the descriptor's namespace-visible UID/GID to be the corresponding overflow identity. This is the same kernel object and authenticated host ownership represented through the one-ID namespace, not rewritten ownership. The observer may open descriptors only in its own process. It must exit successfully and PID 1 must synchronously reap it before the bind; failure, an extra or missing parent fd, an identity or flag mismatch, a non-PID-1 parent, or a surviving observer fails closed.

Only trusted fixed setup may refer to `/proc/self/fd/3`. The checkout bind must be exactly:

```sh
/usr/bin/mount --no-canonicalize --bind /proc/self/fd/3 "$root/src"
```

The fixed absolute mount invocation and option ordering are mandatory. If `/usr/bin/mount` does not support `--no-canonicalize`, or that exact invocation otherwise fails, setup fails closed; default or canonicalizing `mount --bind`, option omission, direct `mount(2)` substitution, fallback, source reopening, `realpath`, `readlink`, pathname recovery, or traversal of the checkout's `/home` ancestors is prohibited. Static companions must require the exact command and reject every canonicalizing or fallback form. PID 1 waits for the mount child, so no mount process retaining fd 3 survives the bind. The retained bind remount is read-only with `nosuid,nodev,noexec`, and all existing exact mount-source, parent, filesystem, option, allowlist, and old-root checks remain mandatory. Synchronous trusted target authentication must compare mounted `/src` with fd 3's exact device, inode, namespace-visible UID/GID, and directory type both before and after the read-only remount, and reject a changed source, target, mount record, or identity. Every target-authentication child that inherited fd 3 must exit and be synchronously reaped before PID 1 continues.

After the no-canonical bind, read-only remount, and all target authentication that requires the reference, PID 1 itself must close fd 3. While PID 1 is again quiescent and waiting, a second newly started synchronous trusted Python observer must inspect its namespace-PID-1 parent at `/proc/<ppid>/fd`, require the parent descriptor names to be exactly `0`, `1`, and `2`, and exit. It must not inherit fd 3, and it may open descriptors only in its own process. PID 1 must synchronously wait for and reap this observer; no observer or other setup child may survive. On exact success, PID 1's immediate next action must be the existing terminal `exec /usr/sbin/chroot ...`, with no intervening command, substitution, diagnostic, fd scan, helper, pathname operation, or other fd-opening operation. No `/proc/self/fd/3` reference, duplicate, reopened checkout descriptor, inherited setup descriptor, checkout ancestor pathname, or observer remains. Checked-out code begins only after this proof, inherits exactly fd 0, fd 1, and fd 2, and never observes fd 3. Descriptors that checked code deliberately creates later for its bounded native primitive tests do not weaken this inherited-empty boundary.

No checkout or ancestor `chmod`, `chown`, ACL, bind of `/home`, copied checkout, supplementary group, subordinate-ID extent, runner-ID extent, multi-ID map, map expansion, capability retention, or initial-namespace capability is authorized. The exact ADR 0075 one-ID map, final all-zero capability sets, inherited seccomp filter, chroot, read-only mount allowlist, and no-socket/no-old-root boundaries remain unchanged.
